Research programme

Overcoming the programming wall.

A heterogeneous system uses more than one kind of processor: a general-purpose CPU to run an operating system, and accelerators such as GPUs and FPGAs to do specific work faster and more efficiently. In the post-Moore era these machines carry the largest applications we have — deep learning and quantum software platforms among them. Extracting performance proportional to the resources in such a system is the problem we work on.

RESEARCH GOALS

Accelerate large-scale applications, pragmatically

The programming wall is an obstacle for general programmers and deep learning model designers who want to parallelize and optimize their applications across the processor resources they already have. We attack it with deep learning models together with compiler, runtime, architecture and operating system techniques at every level.

Areas

Execution platforms for deep learning

As the computation and memory requirements of deep neural networks grow, multi-GPU and multi-node training and inference have become essential — and parallelizing that work requires sophisticated knowledge of the underlying architecture. We build the systems that remove that requirement.

01

Automatic parallelization of DNN models

Parallelizing a DNN training workload across multiple GPUs is challenging: it requires sophisticated knowledge of the underlying system architecture, which hinders users from developing large DNN models. We develop methods to find the best parallelization scheme automatically on a multi-node, multi-GPU system.

We also develop a performance model that predicts how DNN workloads will run on heterogeneous GPUs in a cluster.

ParallelizationPerformance modelsClusters
02

DeepUM and SnuRHAC

DeepUM exploits CUDA Unified Memory to allow GPU memory oversubscription for DNNs. Conventional UM allows oversubscription through page faults, but page migration introduces enormous overhead; DeepUM uses a new correlation prefetching technique to hide it, fully automatically and transparently to the user. We evaluated it on nine large-scale DNNs from MLPerf, PyTorch examples and Hugging Face against six state-of-the-art GPU memory swapping approaches.

SnuRHAC provides the illusion of a single GPU for multiple GPUs in a cluster, distributing workload and managing data across nodes automatically. Evaluated on 18 applications, it achieves scalable performance while significantly reducing the programmer’s burden.

Unified memoryPrefetchingOversubscription
03

Deep learning frameworks for FPGAs and GPUs

As energy efficiency becomes a first-order issue, FPGAs are emerging as promising accelerators for HPC systems — but low-level hardware description languages and vendor toolchains keep them out of reach. We presented SOFF, a high-level synthesis framework for OpenCL and CUDA on FPGAs that requires no explicit user annotations, and we are building an NPU and a deep learning framework that generates an optimal circuit for a given model.

DeepCuts takes the same argument to GPUs: rather than relying on libraries with fixed implementations such as cuDNN, it generates kernels optimized for the target workload and hardware, reaching state-of-the-art performance against TVM, TensorRT and TensorFlow XLA.

04

Mobile ISP replacement through model compression

Deep learning models such as PyNET can replace a mobile image signal processor, but they are expensive to compute and hard to deploy on a phone. We combine Tucker decomposition, quantization, pruning and knowledge distillation to cut computation and memory cost substantially without sacrificing accuracy.

QuantizationPruningDistillation
Areas

Large language models

Large language models are trained mostly on English, and datasets biased toward English produce models that degrade badly on other languages. Much of our work is about closing that gap for Korean, and about making the training affordable enough to do it at all.

01

Korean datasets, tokenizers and models

We are building a massive Korean dataset using web crawling, de-identification and de-duplication, and a deep learning tokenizer for Korean NLP — Korean tokenization involves decomposing words into morphemes (형태소) and tagging their parts of speech (품사).

On top of that data and tokenizer we train Korean language models from scratch, rather than accepting the latency and quality penalty that English-centric models pay on Korean tasks.

Web crawlingDe-identificationMorphemesThunder-LLM
02

Training LLMs under real constraints

Training a model with more than a hundred billion parameters on a cluster runs into the capacity of GPU memory. Parallelizing across GPUs is one answer; using main memory, NVMe SSDs and HDDs as backup space is another. The interaction between the two is non-trivial, so we are building a cluster-targeting framework that uses all of them and a performance model that finds the optimal parallelization.

We also work on training techniques — auto-encoders, layer-wise training, mixtures of experts, better datasets — that make large model training possible without big-tech resources.

GPU memory wallNVMeMixture of experts
03

Energy efficiency and model compression

Energy consumption has become a serious issue in training large language models. We characterise performance and energy on GPUs at the granularity of hardware modules — FPU, tensor core, cache, shared memory — and of deep learning layers, then propose energy-aware parallelization and optimal underclocking.

Separately, we study quantization, pruning and knowledge distillation in depth, and how to combine them properly, so that large models can be deployed on devices with limited computation and memory.

Areas

Quantum computing

01

Software stacks for quantum computing

We are developing an end-to-end software stack for quantum computing: a compiler, a runtime system and a classical quantum-circuit simulator. The current focus is high-performance, scalable simulation and tensor network contraction.

We simulated the 42-qubit quantum supremacy circuit on a workstation-level system with many NVMe SSDs and HDDs. The conventional limit for workstation-level full-state simulation is around 34 qubits, which makes our simulator’s capability 256 times larger. We also built a small cluster with SSDs and HDDs to reach supercomputer-level circuits.

CompilerRuntimeTensor networks
02

SnuQS

SnuQS is a full-state quantum-circuit simulation framework that uses storage devices to enlarge the available main memory capacity at small cost. It partitions circuits automatically based on qubit permutation and amplitude layout, and prefetches amplitudes to overlap computation with I/O.

Combining circuit partitioning with a three-step qubit permutation guarantees that I/O operations are grouped into contiguous blocks large enough to achieve high bandwidth. The result scales full-state simulation of large circuits at about 300× lower cost than a DRAM-only system.

Areas

Under-display camera image restoration

01

Real-world datasets and restoration

An under-display camera sits beneath the display, allowing a larger screen-to-body ratio and better eye tracking. Image quality degrades badly in exchange: light transmittance drops and diffraction takes over.

Previous work relied on synthetic datasets that fail to capture how the degradation actually behaves. We build real-world datasets — UDC-SIT for still images and UDC-VIT for video — and deep learning restoration methods that address the conditions those datasets record.

Practice

How the work gets done

Measured, not asserted

Every systems claim comes with an end-to-end number on hardware we describe. Microbenchmarks are evidence, not conclusions.

Artifacts by default

Code, configurations and traces are released with the paper. If a result cannot be reproduced from the repository, it is not finished.

Two departments, one review

Systems drafts get read by model people and the reverse. It is slower, and it catches the assumptions each side forgot it was making.

Looking for a problem to work on?

Each thread above has open questions we would happily hand to a new student or a visiting collaborator.
